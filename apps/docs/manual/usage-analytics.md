# 用量分析

## 模型性能

选择“模型性能”页签，按模型、时间和高级条件筛选，可查看完整匹配范围的耗时/首响应分位数、全程 TPS、账号成本、吞吐和采集覆盖。点击模型收窄筛选，点击“查看请求”进入监控详情。阈值只保存在当前浏览器并生成页面内提示，不发送外部告警。

无需先设置参数：默认参考标准为多数请求耗时不超过 60 秒、较慢时速度不少于 10 token/s、至少 30 条有效样本后判断。在“调整提醒标准（可选）”中编辑并点击“应用提醒标准”，或用“恢复默认”重置；设置只改变提醒，不改变模型速度或请求超时。

主界面使用中文含义：“典型值”是中间值，“多数请求耗时”覆盖约 95% 的请求，“较慢时的速度”表示约 10% 的请求更慢。完整分位数收在可展开的详细分布中。账号表关联当前认证文件的邮箱、名称与备注；无法关联时明确显示资料不可用，内部标识收在“查看账号标识”中。

旧账号 ID 无法关联当前文件时，会使用历史快照中的邮箱并标注来源；只有邮箱与供应商能唯一对应当前账号时才附上当前备注。历史未记录的备注不会猜测，也不会覆盖当前账号资料。

- 全程 TPS = 输出 token / executor 尝试耗时，仅成功且耗时、输出均有效的事件参与。平均值为逐事件速度的算术平均。
- 首响应是首个上游响应体字节，不一定已经输出文字。耗时不是客户端端到端耗时；内容块不等于 token。
- 请求链路按钮展示实际采集到的阶段和内容块停顿。关联查询限定所选事件前后 24 小时、最多 100 条事件，按尝试 ID 合并拆账；不保证覆盖 reporter 内部所有重试。
- 并发只由有 telemetry 的已结束尝试区间重建，不是实时队列。旧数据缺失字段显示“—”，历史链路不可补回。
- 精确分位数查询最多处理 100000 条匹配事件，超过上限请缩小时间/模型范围；不会静默抽样。成本是按配置价格估算，不能用速度或成功率推断回答质量。

用量分析用来回答“钱花到哪里去了”和“哪些请求造成了异常”。它基于请求监控采集到的事件和 [模型价格](./model-prices.md) 计算，不会改变提供商的真实计费。

## 先选范围

进入页面后先确认时间范围和粒度：

- 今天或最近一小时适合排查刚发生的异常。
- 7 天或 30 天适合看趋势和成本结构。
- 自定义范围适合对齐账单周期或事故时间段。
- 粒度越细，越适合定位峰值；粒度越粗，越适合看趋势。

筛选条件支持模型、API Key、提供商、状态、认证文件、延迟和缓存状态。筛选后，页面里的趋势、排行和明细都会围绕同一批请求计算。

## 主要视图

- **总览**：看请求数、Token、成本、失败率和延迟是否有异常。
- **模型排行**：找出最贵、最多请求或失败最多的模型。
- **API Key 排行**：判断哪个调用方造成成本或失败。
- **认证文件排行**：把用量落到账号，配合配额和巡检使用。
- **趋势图**：观察请求量、成本、Token 和失败率随时间的变化。
- **异常点**：快速定位成本、Token 或失败的突增时间点。
- **热力图**：看调用高峰和低谷，适合调整任务调度。
- **请求预览**：从分析结果跳回请求监控明细。

## 排查成本突增

1. 先看总览是否只有成本升高，还是请求数和失败率也一起升高。
2. 打开模型排行，确认是否某个高价模型占比异常。
3. 打开 API Key 排行，确认是否某个调用方突然增加请求。
4. 打开认证文件排行，确认是否某个账号或项目集中消耗。
5. 点击请求预览或“查看请求监控明细”，回到单条请求核对模型名、Token 和调用方。

如果模型名是别名或内部模型，先到 [模型价格](./model-prices.md) 补全价格，否则成本会低估或无法估算。

## 准确性边界

- 提供商实际账单以提供商为准。
- CPAMP 根据请求事件和模型价格估算成本。
- 如果模型名被客户端、提供商或路由别名改写，需要在模型价格中维护对应名称。
- 缺失 Token 字段时，成本可能无法完整估算。
- Manager Server 停机或队列过期期间丢失的请求事件无法补回。
